Faza czwarta
VoIP i QoS
VoIP jest ekstremalnie wrażliwy na opóźnienia i jitter. Jeden błędny parametr = przerywający dźwięk, echo lub zrywające się połączenia. Skonfiguruj to poprawnie.
⏱ 1 tydzień • uwaga na SIP ALG!
SIP ALG – największy wróg VoIP
✓
SIP ALG – co to jest i czy wyłączyć?
VOIPKRYTYCZNE
▾
SIP ALG (Application Layer Gateway) to mechanizm który modyfikuje pakiety SIP w locie – repisuje adresy IP wewnątrz nagłówków SIP żeby NAT działał poprawnie. Problem: wiele nowoczesnych central VoIP (FreePBX, 3CX, Asterisk, Panasonic, Cisco UCM) samo sobie radzi z NAT i SIP ALG tylko psuje pakiety.
Objawy działającego SIP ALG który szkodzi
✗ Telefony rejestrują się, ale połączenia nie przechodzą
✗ Słychać tylko jedną stronę rozmowy (problem z RTP)
✗ Połączenia zrywają się po 30-90 sekundach (timer BYE)
✗ INVITE trafia do centrali ale centrala nie może zadzwonić z powrotem
✗ Numer dzwoniącego pokazuje się błędnie
🚨
Zasada praktyczna
Jeśli masz jakikolwiek problem z VoIP przez FortiGate – pierwsza rzecz: wyłącz SIP ALG. 80% problemów znika. Ponownie włączaj tylko jeśli masz konkretny powód (niektóre stare centrale tego wymagają).
Wyłączenie SIP ALG przez CLI (wymagane po przez config)
# Wyłącz SIP helper (ALG)
config system settings
  set sip-helper disable
  set sip-nat-trace disable
end

# Wyłącz SIP session helper
config system session-helper
  # Znajdź numer wpisu SIP
  show
  # Przykładowo jeśli SIP to wpis 13:
  delete 13
end

# Sprawdź czy wyłączono poprawnie
get system settings | grep sip
✓
Polityki firewall dla VoIP – porty SIP i RTP
VOIPGUIWAŻNE
▾
VoIP używa dwóch rodzajów ruchu: sygnalizacji SIP (nawiązywanie i rozłączanie połączeń) oraz strumieni RTP (rzeczywisty dźwięk). Oba muszą być odblokowane.
PortProtoKierunekOpis
5060UDP/TCPObydwaSIP – sygnalizacja (standard)
5061TLSObydwaSIPS – szyfrowana sygnalizacja
10000–20000UDPObydwaRTP – strumień audio (zakres typowy)
16384–32767UDPObydwaRTP – zakres dla niektórych central Cisco
Utwórz Service Group: Policy & Objects → Services → Create New → Service Group → nazwa: VOIP_PORTS
Dodaj: SIP (UDP 5060), SIP-TCP (TCP 5060), RTP (UDP 10000-20000)
Polityka dla telefonów hosted PBX (w chmurze): Src = TELEFONY_VOIP, Dst = IP_centrali_lub_all, Service = VOIP_PORTS, Action = ACCEPT, NAT = ON
Polityka dla centrali lokalnej: Src = TELEFONY_VOIP, Dst = IP_centrali (LAN), Service = VOIP_PORTS, Action = ACCEPT, NAT = OFF
Sniffer SIP – diagnostyka
# Podsłuchaj sygnalizację SIP (Ctrl+C aby zatrzymać)
diagnose sniffer packet any "port 5060" 4

# Sniffer z filtrem IP centrali
diagnose sniffer packet any "host 10.10.0.100 and port 5060" 4

# Sprawdź aktywne sesje VoIP
diagnose sys session filter proto 17
diagnose sys session filter dport 5060
diagnose sys session list

QoS Traffic Shaping – priorytet głosu nad danymi
VOIPGUI
▾
Gdy 120 userów pobiera pliki i aktualizacje Windows, VoIP może dostać za mało pasma → przerwy w rozmowach. QoS (Quality of Service) gwarantuje że głos zawsze ma pierwszeństwo.
Jak działa Traffic Shaping w FortiGate
Traffic Shaper – definiuje prędkość (guaranteed / maximum) i priorytet
Traffic Shaping Policy – przypisuje shaper do konkretnego ruchu (src IP, service, interface)

Priorytety: Highest → High → Medium → Low → Lowest
Policy & Objects → Traffic Shapers → Create New (Shared Shaper)
Shaper VOIP-Guaranteed: Priority = Highest, Guaranteed Bandwidth = 2048 kbps (2 Mbps), Max = 5120 kbps
Shaper WindowsUpdate: Priority = Low, Max = 20480 kbps (nie blokuj, tylko ogranicz priorytet)
Policy & Objects → Traffic Shaping Policy → Create New
Reguła VoIP: Source = TELEFONY_VOIP, Service = VOIP_PORTS, Apply Shaper = VOIP-Guaranteed
Reguła WinUpdate: Destination = windowsupdate.microsoft.com (FQDN), Apply Shaper = WindowsUpdate
ℹ️
DSCP i oznaczanie pakietów
Zamiast shapera możesz oznaczyć pakiety VoIP tagiem DSCP EF (Expedited Forwarding = wartość 46 = 0xB8). Routery i switche "widzą" ten tag i automatycznie priorytetyzują. W Shaper Policy: DSCP Marking = EF.
