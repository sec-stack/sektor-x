Architektura i dostęp
✓
Jak działa FortiGate – architektura ASIC i NP7
TEORIA
▾
FortiGate to Next-Generation Firewall (NGFW) wyposażony we własne układy ASIC (Application-Specific Integrated Circuit). Model 60F zawiera procesor NP6Lite, a 120G już pełen NP7 – dzięki temu część ruchu jest przetwarzana sprzętowo, a nie przez CPU, co daje gigabitowe przepustowości bez zauważalnego obciążenia procesora.
Kluczowe pojęcia
FortiOS – system operacyjny FortiGate (aktualna gałąź: 7.4.x / 7.6.x)
ASIC NP7 – sprzętowe przyspieszenie: firewall, IPsec VPN, routing
Content Processor (CP9) – obsługuje SSL/TLS inspekcję, antywirus, IPS
SPU – Security Processing Unit: kombinacja NP + CP
FortiGuard – chmura Fortinet dostarczająca sygnatury AV, IPS, URL filtering, aktualizowane co kilkanaście minut
ℹ️
60F vs 120G
60F: 10 GE portów RJ45, NP6Lite, firewall do ~10 Gbps, rekomendowany do ~80 userów. 120G: NP7, więcej portów SFP, obsługuje do ~200 userów i oferuje wyższą wydajność SSL inspekcji – lepszy wybór dla Twojego środowiska 120 userów.

Backup i restore konfiguracji – rutyna admina
GUICLIWAŻNE
▾
Backup to Twoje ubezpieczenie. Rób go przed każdą zmianą i przechowuj poza urządzeniem (USB, serwer plików, chmura). Plik .conf to zwykły tekst – możesz go otworzyć notatnikiem i przejrzeć całą konfigurację.
GUI backup: System → Configuration → Backup → wybierz "Local PC" → zapisz plik .conf
Opcjonalnie: zaszyfruj backup hasłem (pole "Encrypt configuration file") – ważne jeśli backup zawiera hasła VPN, PSK itp.
Restore: System → Configuration → Restore → wgraj plik → FortiGate zrestartuje się i wczyta konfigurację
Po restore sprawdź: get system status i przetestuj dostęp do internetu
Backup przez CLI (SCP na serwer)
# Backup na serwer FTP/SCP
execute backup config sftp backup.conf 192.168.1.10 admin haslo

# Backup na USB (jeśli podłączony)
execute backup config usb backup_$(date).conf

# Sprawdź aktualną konfigurację (wylistuj)
show full-configuration | grep -i hostname
✅
Dobra praktyka
Zapisuj backupy z datą w nazwie: FW-FIRMA_2025-01-15.conf. Trzymaj przynajmniej 3 ostatnie wersje. Raz w miesiącu przetestuj restore na środowisku testowym lub laboratoryjnym (FortiGate VM jest bezpłatny do pobrania).

Aktualizacja FortiOS – kiedy i jak
GUIWAŻNE
▾
Fortinet regularnie wydaje aktualizacje bezpieczeństwa. Ważne: nie aktualizuj automatycznie w produkcji. Czytaj Release Notes, testuj na VM lub poza godzinami pracy.
Numery wersji FortiOS
Format: 7.4.3 build 2573 – major.minor.patch build
Gałąź 7.4.x – stabilna, rekomendowana dla środowisk produkcyjnych
Gałąź 7.6.x – najnowsza, może mieć więcej bugów w pierwszych patchach
Fortinet oznacza wersje: ● GA (General Availability) | ● MR (Maintenance Release)
Zrób backup konfiguracji przed aktualizacją!
System → Firmware → sprawdź dostępne wersje (kliknij "Check for Updates")
Przeczytaj Release Notes na docs.fortinet.com – szukaj sekcji "Known Issues" i "Upgrade Path"
Jeśli aktualizujesz przez kilka gałęzi (np. 7.2 → 7.4), przejdź przez pośrednie wersje zgodnie z Upgrade Path
Kliknij "Upgrade" → FortiGate pobierze firmware i zrestartuje się (~5 min)
Po restarcie: sprawdź status, przetestuj polityki i VoIP
🚨
Uwaga na Upgrade Path
Nie można przeskoczyć zbyt wielu wersji naraz. Zawsze sprawdź Upgrade Path Tool na support.fortinet.com. Np. z 7.0 → 7.4 musisz przez 7.2. Pominięcie grozi uszkodzeniem konfiguracji.

Konfiguracja interfejsu WAN – połączenie z ISP
GUICLIKLUCZOWE
▾
Interfejs WAN to "wyjście na świat". Zazwyczaj dostarcza go ISP jako DHCP lub statyczny IP. W FortiGate jest to zazwyczaj wan1.

# Sprawdź czy masz domyślną trasę
get router info routing-table all

# Ping do bramy ISP (test WAN)
execute ping 8.8.8.8

# Ping ze wskazanego interfejsu
execute ping-options source wan1
execute ping 8.8.8.8

GUICLIWAŻNE
▾

Firewall i Polityki
Serce FortiGate. Polityki decydują co może przejść przez firewall, w którą stronę i z jakimi profilami bezpieczeństwa. To najważniejsza umiejętność admina.
⏱ 2–3 tygodnie • priorytet: KRYTYCZNY
Logika i teoria
✓
Jak działają polityki – przepływ pakietu przez FortiGate
TEORIAKLUCZOWE
▾
Pakiet wchodzący do FortiGate przechodzi przez ściśle określony pipeline. Zrozumienie kolejności przetwarzania to fundament diagnostyki.
Kolejność przetwarzania pakietu
1. Routing – FortiGate sprawdza tablicę routingu: skąd i dokąd pakiet jedzie
2. Session Lookup – czy to nowa czy istniejąca sesja? (stateful firewall)
3. DoS Policy – ochrona przed atakami DoS (opcjonalne)
4. Firewall Policy – pierwsza pasująca reguła od góry listy wygrywa → ACCEPT lub DENY
5. Security Profiles – AV, IPS, Web Filter, App Control (tylko dla ACCEPT)
6. NAT – tłumaczenie adresów (Source NAT dla wyjścia do internetu)
7. Forwarding – pakiet zostaje wysłany dalej
ℹ️
Stateful vs Stateless
FortiGate to firewall stateful – śledzi sesje TCP/UDP. Jeśli akceptujesz ruch LAN→WAN, odpowiedź z WAN→LAN jest automatycznie przepuszczana bez dodatkowej reguły. Nie musisz tworzyć reguły "powrotnej".
✓
Obiekty adresów i grupy – buduj przed politykami
GUIWAŻNE
▾
Zamiast wpisywać surowe IP w politykach, twórz obiekty adresów. Gdy zmieni się IP drukarki, zmienisz go raz w obiekcie – polityki zaktualizują się automatycznie.
Policy & Objects → Addresses → Create New → Address
Typy obiektów: Subnet (zakres sieci), IP Range (np. 10.10.0.20-10.10.0.30), FQDN (nazwa DNS), Wildcard FQDN (*.google.com)
Utwórz: DRUKARKI = 10.10.0.20-10.10.0.29, TELEFONY_VOIP = 10.10.0.30-10.10.0.50, SERWERY = 10.10.0.10-10.10.0.15
Grupy: Policy & Objects → Addresses → Create New → Address Group. Pogrupuj DRUKARKI + TELEFONY jako URZADZENIA_BIUROWE
Tworzenie obiektu adresu przez CLI
config firewall address
  edit "DRUKARKI"
    set type iprange
    set start-ip 10.10.0.20
    set end-ip 10.10.0.29
    set comment "Drukarki biurowe – piętro 1 i 2"
  next
end
✓
Pierwsza polityka: LAN → Internet (z NAT)
GUISTART
▾
To podstawowa reguła, bez której userzy nie mają internetu. Ruch z LAN wychodzi na WAN z translacją adresu (NAT) – zewnętrzny świat widzi publiczny IP FortiGate, nie prywatne IP usera.
Policy & Objects → Firewall Policy → Create New
Name: LAN-do-Internet
Incoming Interface: internal (LAN)
Outgoing Interface: wan1
Source: all (lub obiekt LAN_USERS)
Destination: all
Service: ALL (na start, zawęź później)
Action: ACCEPT
NAT: ON → "Use Outgoing Interface Address" (FortiGate podstawia swój IP WAN)
Logging: Log Allowed Traffic → All Sessions (obowiązkowo!)
Kliknij OK – testuj przez ping z komputera usera
⚠️
Zasada minimalnych uprawnień
Reguła ALL→ALL jest dobra na start, ale docelowo zawęź Service do potrzebnych protokołów: HTTP, HTTPS, DNS, SMTP, IMAP, POP3. Blokowanie niepotrzebnych portów zmniejsza ryzyko ataków i C2 (command & control botnetów).
✓
Polityki dla drukarek – ograniczenie ruchu
GUIBEZP.
▾
Drukarki sieciowe nie powinny mieć dostępu do internetu – to potencjalny wektor ataku. Skonfiguruj politykę pozwalającą tylko na drukowanie i zarządzanie w sieci LAN.
PortProtokółZastosowanie
9100TCPRAW printing (JetDirect) – podstawowe drukowanie
631TCPIPP – Internet Printing Protocol
161UDPSNMP – monitorowanie stanu drukarki
80/443TCPPanel web drukarki (zarządzanie)
515TCPLPR/LPD – starszy protokół druku
Utwórz Custom Service: Policy & Objects → Services → Create New → nazwa: DRUKOWANIE, dodaj porty TCP 9100, 631, 515 i UDP 161
Utwórz politykę: Src = DRUKARKI, Dst = all (LAN), Service = DRUKOWANIE, Action = ACCEPT
Utwórz politykę blokującą wyjście drukarek na internet: Src = DRUKARKI, Dst = all, Out = wan1, Action = DENY
Kolejność: reguła DENY dla drukarek PRZED ogólną regułą LAN→Internet!
✓
Virtual IPs i NAT – dostęp z zewnątrz do wewnętrznych zasobów
GUICLI
▾
Virtual IP (VIP) to mechanizm Destination NAT – mapujesz zewnętrzny IP i port na wewnętrzny serwer. Używaj np. do udostępnienia serwera plików lub kamery IP z zewnątrz.
Policy & Objects → Virtual IPs → Create New → Virtual IP
External IP: publiczny IP FortiGate (lub zakres)
Mapped IP: wewnętrzny IP serwera, np. 10.10.0.11
Włącz Port Forwarding jeśli chcesz mapować tylko jeden port (np. zewnętrzny 8443 → wewnętrzny 443)
Utwórz politykę: In = wan1, Out = internal, Dst = VIP, Service = HTTPS, Action = ACCEPT
🚨
Bezpieczeństwo VIP
Każdy VIP to "dziura" do sieci wewnętrznej. Zawsze: ograniczaj Source w polityce do konkretnych IP (np. tylko siedziba centrali), włącz IPS na tej polityce, używaj niestandardowych portów zewnętrznych.
✓
Policy Lookup i diagnostyka polityk
GUICLITIP
▾
Zanim zadzwoni user z "internet nie działa" – wiesz gdzie szukać. Trzy kluczowe narzędzia diagnostyczne polityk.
1. Policy Lookup (GUI)
Policy & Objects → Policy Lookup. Wpisz: Source IP, Destination IP, Protocol/Port. Wynik: która reguła pasuje i co robi. Idealne do testowania przed wdrożeniem.
2. Logi ruchu (GUI)
Log & Report → Forward Traffic. Filtruj po IP źródłowym usera. Kolumna "Policy" pokazuje numer reguły, "Action" = accept/deny. Kliknij na log → szczegóły sesji.
3. Debug flow (CLI) – najpotężniejsze narzędzie
# Krok 1: Wyczyść poprzednie flagi
diagnose debug reset

# Krok 2: Ustaw filtr na IP usera
diagnose debug flow filter addr 10.10.0.55

# Krok 3: Włącz trace (6 = szczegółowy)
diagnose debug flow trace start 100
diagnose debug enable

# Obserwuj output – user generuje ruch
# Po zakończeniu:
diagnose debug disable
diagnose debug reset
✅
Odczyt debug flow
Szukaj linii: iprope_in_check() check failed on policy X – oznacza blokadę przez regułę X. Linia find a route: gw-X.X.X.X via wan1 – pakiet ma trasę. no session matched – nowa sesja, sprawdzana przez polityki.

Routing i DNS
✓
Routing statyczny – domyślna trasa i trasy wewnętrzne
GUICLIKLUCZOWE
▾
FortiGate musi wiedzieć dokąd wysyłać pakiety. Dla prostej sieci wystarczy domyślna trasa (default route) wskazująca na bramę ISP. Dla złożonych sieci dodajesz trasy statyczne do poszczególnych podsieci.
Network → Static Routes → Create New
Destination: 0.0.0.0/0 (default route – pasuje do wszystkiego)
Gateway: IP bramy ISP (dostaniesz od dostawcy lub z DHCP)
Interface: wan1
Distance: 10 (niższa wartość = wyższy priorytet)
Diagnostyka routingu
# Pełna tablica routingu
get router info routing-table all

# Konkretna trasa do danego IP
get router info routing-table details 8.8.8.8

# Traceroute z FortiGate
execute traceroute 8.8.8.8

# Sprawdź ARP (kto odpowiada na LAN)
get system arp
✓
DNS – konfiguracja i FortiGate jako DNS forwarder
GUIWAŻNE
▾
Przy środowisku z Active Directory (Windows Server) musisz ostrożnie skonfigurować DNS – błędy DNS powodują problemy z logowaniem do domeny i GPO.
Dwa scenariusze DNS
Scenariusz A – Bez Windows AD:
DNS FortiGate: 8.8.8.8 + 1.1.1.1. W DHCP serwer DNS = 10.10.0.1 (FortiGate jako forwarder)

Scenariusz B – Z Windows Active Directory (zalecane):
DNS FortiGate: IP Twojego Windows DNS (np. 10.10.0.10). W DHCP serwer DNS = 10.10.0.10 (Windows DNS bezpośrednio). Windows DNS forwarduje zewnętrzne zapytania do 8.8.8.8.
Network → DNS → Primary DNS Server: IP Twojego Windows DNS lub 8.8.8.8
Jeśli chcesz FortiGate jako DNS proxy: Network → DNS → zaznacz "Listen on Interfaces" → wybierz internal
W DHCP Server → DNS Server: wpisz IP FortiGate LAN (10.10.0.1) jeśli FortiGate ma być pośrednikiem
✅
FortiGuard DNS Filter
Gdy włączysz DNS Filter (Security Profile), FortiGate może blokować domeny złośliwego oprogramowania i botnetów na poziomie DNS – zanim pakiet trafi do firewall policy. Bardzo skuteczna ochrona przy minimalnym wpływie na wydajność.
✓
SD-WAN – redundancja i load balancing (dwa łącza ISP)
GUIWARTO
▾
Jeśli masz dwa łącza internet (np. światłowód + LTE backup), SD-WAN automatycznie przełącza ruch gdy jedno łącze padnie. Dla 120 userów to znacząca poprawa dostępności.
Network → SD-WAN → Enable SD-WAN
Dodaj oba interfejsy WAN jako "Member": wan1 (główne), wan2 lub modem LTE
Ustaw Performance SLA: cel monitorujący – np. ping do 8.8.8.8 co 5 sekund, próg latencji 200ms, próg utraty pakietów 10%
Reguła SD-WAN: tryb Failover – wan1 jest aktywny, wan2 przejmuje tylko gdy wan1 nie spełnia SLA
Dla zaawansowanych: tryb Load Balance – ruch rozkładany na oba łącza (per session lub per IP)
SD-WAN Rules – inteligentny routing
Możesz skierować konkretny ruch na konkretne łącze:
– VoIP (UDP 5060, 10000-20000) → wan1 (niższe opóźnienia, światłowód)
– Backup / Windows Update → wan2 (nie zapycha głównego łącza)
– Reszta → load balance lub failover
✓

PRZYSZŁOŚĆ
▾
Teraz masz płaską sieć – wszystko w jednej podsieci. To działa, ale rośnie ryzyko: drukarka może "rozmawiać" z serwerem AD bez przeszkód. VLANy rozdzielają ruch logicznie bez dodatkowych kabli.

FortiSwitch zarządzany przez FortiGate (FortiLink) to najbardziej płynna opcja. Konfigurujesz switche z poziomu FortiGate GUI, VLANy propagują się automatycznie, możesz stosować polityki per-port. Warto rozważyć przy rozbudowie.

Faza czwarta
VoIP i QoS
VoIP jest ekstremalnie wrażliwy na opóźnienia i jitter. Jeden błędny parametr = przerywający dźwięk, echo lub zrywające się połączenia. Skonfiguruj to poprawnie.
⏱ 1 tydzień • uwaga na SIP ALG!
SIP ALG – największy wróg VoIP
✓
SIP ALG – co to jest i czy wyłączyć?
VOIPKRYTYCZNE
▾
SIP ALG (Application Layer Gateway) to mechanizm który modyfikuje pakiety SIP w locie – repisuje adresy IP wewnątrz nagłówków SIP żeby NAT działał poprawnie. Problem: wiele nowoczesnych central VoIP (FreePBX, 3CX, Asterisk, Panasonic, Cisco UCM) samo sobie radzi z NAT i SIP ALG tylko psuje pakiety.
Objawy działającego SIP ALG który szkodzi
✗ Telefony rejestrują się, ale połączenia nie przechodzą
✗ Słychać tylko jedną stronę rozmowy (problem z RTP)
✗ Połączenia zrywają się po 30-90 sekundach (timer BYE)
✗ INVITE trafia do centrali ale centrala nie może zadzwonić z powrotem
✗ Numer dzwoniącego pokazuje się błędnie
🚨
Zasada praktyczna
Jeśli masz jakikolwiek problem z VoIP przez FortiGate – pierwsza rzecz: wyłącz SIP ALG. 80% problemów znika. Ponownie włączaj tylko jeśli masz konkretny powód (niektóre stare centrale tego wymagają).
Wyłączenie SIP ALG przez CLI (wymagane po przez config)
# Wyłącz SIP helper (ALG)

SSL/TLS Inspection – inspekcja szyfrowanego HTTPS
BEZP.TEORIA
▾
~90% ruchu w internecie to HTTPS – szyfrowany. Bez SSL Inspection, AV i IPS widzą tylko zaszyfrowane bałaganiny. Są dwa tryby:
Certificate Inspection (zalecane na start)
FortiGate sprawdza certyfikat serwera ale nie deszyfruje treści. Może blokować złe certyfikaty, wyciągać SNI (nazwę domeny) do Web Filter. Nie wpływa na wydajność, nie wymaga instalacji certyfikatu CA na komputerach. Włącz to zawsze.

FortiGate deszyfruje, skanuje, ponownie szyfruje każde połączenie HTTPS. Pełna widoczność zawartości dla AV, IPS, DLP. Wymaga: zainstalowania certyfikatu CA FortiGate na każdym komputerze (przez GPO w AD). Uwaga na prywatność (banking, ZUS, e-commerce) – dodaj wyjątki dla tych kategorii.

Eksportuj certyfikat CA: Security Profiles → SSL/SSH Inspection → Download Certificate
Zainstaluj przez GPO: Computer Configuration → Policies → Windows Settings → Security Settings → Public Key Policies → Trusted Root Certification Authorities

VLANy – Segmentacja sieci 802.1Q
VLANy dzielą jedną fizyczną sieć na izolowane segmenty logiczne. Drukarki nie widzą serwerów, telefony VoIP mają własną domenę rozgłoszeniową, a zarządzanie jest oddzielone od userów. Krok po kroku od zera.
⏱ 1–2 tygodnie • wymaga switcha zarządzalnego
Teoria i planowanie
✓
Co to jest VLAN i jak działa 802.1Q
TEORIASTART
▾
VLAN (Virtual Local Area Network) to logiczne wydzielenie segmentu sieci na poziomie warstwy 2 (ramki Ethernet). Urządzenia w różnych VLANach nie widzą się nawzajem bez routera – nawet jeśli podłączone są do tego samego switcha.
Jak działa tag 802.1Q
Standard IEEE 802.1Q dodaje do ramki Ethernet 4-bajtowy tag zawierający numer VLAN (VID, 1–4094). Switch "widzi" tag i wie do którego VLANu należy ramka.

Access port – port bez tagu, podłączony do urządzenia końcowego (PC, drukarka, telefon). Switch dodaje/usuwa tag automatycznie.
Trunk port – port z tagami wielu VLANów, łączy switche między sobą i z FortiGate. Ramki różnych VLANów płyną jednym kablem.
Dlaczego warto – korzyści dla Twojego środowiska
✅ Bezpieczeństwo: drukarka zainfekowana złośliwym firmware nie dotrze do serwera AD
✅ Mniejszy broadcast domain: ARP i NetBIOS nie zalewają całej sieci 120 urządzeń
✅ Jakość VoIP: telefony mają własny segment – żadne storm broadcastowe nie psują głosu
✅ Łatwiejsze zarządzanie: polityki FortiGate per VLAN, osobny DHCP, osobne IP
✅ Compliance: segmentacja wymagana przez ISO 27001, PCI-DSS
ℹ️
Co potrzebujesz sprzętowo
FortiGate 60F/120G obsługuje VLANy natywnie. Potrzebujesz też switcha zarządzalnego obsługującego 802.1Q (np. FortiSwitch, Cisco Catalyst, HP/Aruba, TP-Link JetStream, Netgear Smart). Tani switch niezarządzalny NIE obsługuje VLANów.

Macierz komunikacji – co pozwolić, co zablokować
Źródło → CelAkcjaSerwisy
USERS → WANALLOWHTTP, HTTPS, DNS
USERS → SERVERSALLOWSMB(445), RDP(3389), DNS(53), Kerberos(88)
USERS → PRINTERSALLOWTCP 9100, 631, 515
USERS → VOIPDENYUserzy nie powinni gadać z telefonami
PRINTERS → WANDENYDrukarki bez internetu
PRINTERS → SERVERSALLOWTCP 443 (print server), SNMP 161
VOIP → WANALLOWUDP 5060, UDP 10000-20000 (hosted PBX)
VOIP → USERSDENYIzolacja VoIP
GUEST → WANALLOWHTTP, HTTPS tylko
GUEST → pozostałeDENYPełna izolacja gości

Policy & Objects → Firewall Policy → Create New
Polityka USERS→SERVERS: In=VLAN10-USERS, Out=VLAN40-SERVERS, Src=all, Dst=all, Service=stwórz custom "AD-SERVICES" (445,88,389,3389,53), Action=ACCEPT
Polityka USERS→PRINTERS: In=VLAN10, Out=VLAN20, Service=DRUKOWANIE, Action=ACCEPT
Polityka blokująca PRINTERS→WAN: In=VLAN20, Out=wan1, Action=DENY – przed ogólną regułą LAN→WAN
Polityka GUEST→LAN (deny): In=VLAN50-GUEST, Out=VLAN10,20,30,40, Action=DENY
⚠️
Kolejność polityk jest krytyczna
Reguły DENY dla konkretnych VLANów muszą być WYŻEJ niż ogólna reguła "LAN→Internet ALLOW". FortiGate czyta od góry – pierwsza pasująca wygrywa.
Konfiguracja switcha
✓
Switch zarządzalny – trunk i access porty
CLIWAŻNE
▾
Switch musi wiedzieć które porty są "trunk" (niosą wiele VLANów – do FortiGate i między switchami) a które "access" (jeden VLAN – do PC, drukarki, telefonu).
Topologia fizyczna
FortiGate (internal) ←─ trunk (VLANy 10,20,30,40,99) ─→ Switch główny

Na switchu głównym:
– Port do FortiGate: trunk, allowed VLANs: 10,20,30,40,50,99
– Port do PC (user): access VLAN 10
– Port do drukarki: access VLAN 20
– Port do telefonu IP: access VLAN 30 (lub voice VLAN jeśli switch wspiera)
Cisco IOS / Catalyst (przykład)
# Port trunk do FortiGate
interface GigabitEthernet0/1
 switchport mode trunk
 switchport trunk allowed vlan 10,20,30,40,50,99
 switchport trunk native vlan 99

# Port access – stacja robocza
interface GigabitEthernet0/5
 switchport mode access
 switchport access vlan 10
 spanning-tree portfast

# Port access – drukarka
interface GigabitEthernet0/10
 switchport mode access
 switchport access vlan 20

# Port access + voice VLAN – telefon IP
interface GigabitEthernet0/15
 switchport mode access
 switchport access vlan 10 # VLAN danych (PC za telefonem)
 switchport voice vlan 30 # VLAN głosowy (telefon)
FortiSwitch (zarządzany przez FortiGate – FortiLink)
# W FortiGate GUI: WiFi & Switch Controller → FortiSwitch Ports
# Kliknij port → Native VLAN = 10 (users) lub 20 (printers)
# Allowed VLANs = tylko VLAN dla tego portu

# Przez CLI FortiGate (FortiLink)
config switch-controller managed-switch
  edit "S124DN3X00000000" # serial switcha
    config ports
      edit "port5"
        set vlan "VLAN10-USERS"
      next
    end
  next
end

Migracja z płaskiej sieci na VLANy – plan bez przestoju
KRYTYCZNEPLANOWANIE
▾
Najtrudniejsza część: przejście z obecnej płaskiej sieci (jedna podsieć dla wszystkich) na VLANy bez wyłączenia 120 userów na cały dzień. Dobrze zaplanowana migracja trwa 2-4 godziny po godzinach pracy.
Etap 1 – Przygotowanie (bez wpływu na produkcję): Utwórz interfejsy VLAN na FortiGate, skonfiguruj DHCP per VLAN, utwórz polityki inter-VLAN. Jeszcze nie podłączaj switcha trunk.
Etap 2 – Testowy VLAN: Podłącz jeden switch testowy z VLAN 10. Podłącz jeden PC testowy. Sprawdź: DHCP, internet, dostęp do serwerów AD, drukowanie. Testuj przez tydzień.
Etap 3 – Migracja switchy (po godzinach): Jeden switch na raz. Zmień porty uplink na trunk. Przestaw porty urządzeń na odpowiednie VLANy. Przy FortiSwitch – zmiany przez GUI FortiGate.
Etap 4 – Weryfikacja: Sprawdź: DHCP leases per VLAN, ping między VLANami (powinien działać zgodnie z politykami), brak dostępu gości do zasobów LAN.
Etap 5 – Dokumentacja: Narysuj diagram sieci z VLANami, opisz każdy port switcha, zapisz w systemie dokumentacji.

Pułapka – Windows AD i VLANy

Faza ósma
VDOMy – Virtual Domains
VDOM to jak uruchomienie wielu wirtualnych FortiGate'ów na jednym fizycznym urządzeniu. Każdy VDOM ma własne polityki, routing, interfejsy, admina. Zaawansowane – ale warto wiedzieć kiedy i po co.
⏱ 1 tydzień • zaawansowany temat
Teoria i zastosowania
✓
Co to jest VDOM i czym różni się od VLANa
TEORIASTART
▾
VDOM (Virtual Domain) to pełna wirtualizacja instancji FortiGate. Każdy VDOM ma własny: zestaw interfejsów, tablicę routingu, polityki firewall, profile bezpieczeństwa, konfigurację VPN, oddzielnych administratorów i osobne logi. Jeden fizyczny sprzęt = wiele niezależnych firewalli.
VDOM vs VLAN – kluczowa różnica
CechaVLANVDOM
Co separujeRuch L2/L3Całą konfigurację firewall
Własny routing❌ (wspólny)✅ osobna tablica
Własne polityki❌ (wspólna baza)✅ całkowicie osobne
Własny admin❌✅ osobne konto admina per VDOM
Własne VPN❌✅ niezależne tunele
Własny WANWspólny (lub kilka)✅ dedykowany interfejs WAN per VDOM
Kiedy używaćSegmentacja jednej firmyMulti-tenant, oddziały, MSP
ℹ️
Domyślny VDOM – root
Każdy FortiGate startuje z jednym VDOMem o nazwie root. Jeśli nie włączysz trybu multi-VDOM, pracujesz w root i możesz o VDOMach zapomnieć. Włączenie multi-VDOM wymaga restartu i nieco reorganizacji konfiguracji.
✓
Kiedy używać VDOMów – przypadki użycia
TEORIA
▾
VDOMy mają sens w konkretnych scenariuszach. Dla pojedynczej firmy z 120 userami zazwyczaj VDOMy nie są potrzebne – VLANy wystarczą. Ale warto wiedzieć kiedy sięgnąć po VDOMy.
✅ Kiedy VDOMy mają sens
1. Multi-tenant / MSP: dostarczasz usługi firewall wielu klientom z jednego urządzenia. Klient A nie widzi konfiguracji Klienta B. Każdy ma swojego admina VDOM.

2. Oddziały firmy z różnymi politykami: Oddział Warszawa i Kraków na tym samym FortiGate w DC – różne polityki, różne VPN, różni admini oddziałów.

3. Separacja środowisk: VDOM "Produkcja" i VDOM "Dev/Test" – programiści nie mogą przypadkowo wpłynąć na produkcję.

4. Compliance i audyt: PCI-DSS wymaga separacji środowiska płatności od reszty sieci. VDOM daje twardą granicę.

5. Różne łącza ISP per departament: Zarząd ma dedykowane łącze 1 Gbps (VDOM-MGMT), reszta korzysta ze wspólnego (VDOM-USERS).
❌ Kiedy VDOMy NIE mają sensu
– Mała/średnia firma z jednorodną polityką bezpieczeństwa
– Brak potrzeby osobnych adminów
– Wszystkie urządzenia należą do jednej organizacji
– VLANy + odpowiednie polityki inter-VLAN w zupełności wystarczają
– Masz mało zasobów sprzętowych (każdy VDOM "zużywa" część RAM/CPU)

✓

✓
Administratorzy per VDOM – delegacja uprawnień
GUIWAŻNE
▾
Jedną z największych zalet VDOMów jest możliwość stworzenia admina który widzi tylko swój VDOM. Admin Klienta A nie może wejść do konfiguracji Klienta B ani do ustawień globalnych.
Typy adminów w multi-VDOM
Super_Admin – widzi wszystko: Global + wszystkie VDOMy. Tylko dla Ciebie jako głównego admina.

VDOM Admin – dostęp tylko do przypisanych VDOMów. Może tworzyć polityki, zarządzać użytkownikami, VPN – ale nie może zmieniać globalnych ustawień ani widzieć innych VDOMów.

Read-Only Admin – tylko podgląd, bez możliwości zmian. Dobre dla audytorów lub helpdesk.
System → Administrators → Create New
Username: np. admin-klient-a
Type: Regular
Admin Profile: prof_admin (pełny dostęp) lub stwórz custom profil
Virtual Domain: wybierz tylko KLIENT-A
Ustaw silne hasło i włącz Two-Factor Authentication (FortiToken lub email)
Tworzenie admina VDOM przez CLI
config global
config system admin
  edit "admin-klient-a"
    set password SuperSilneHaslo123!
    set accprofile "prof_admin"
    set vdom "KLIENT-A"
  next
end
✓
Inter-VDOM Link – komunikacja między VDOMami
GUICLI
▾
VDOMy są domyślnie całkowicie odizolowane – nie widzą się nawzajem. Jeśli chcesz żeby ruch między VDOMami przechodził (np. oba korzystają ze wspólnego WAN w "root") – potrzebujesz Inter-VDOM Link (vdom-link).
Typowa architektura z Inter-VDOM Link
KLIENT-A (LAN) ──→ vdom-link ──→ root (WAN) ──→ Internet

VDOM root zarządza połączeniem WAN i NAT. KLIENT-A ma swoją sieć LAN i polityki, ale ruch internetowy przechodzi przez root. Jest to jak "wirtualny kabel" między VDOMami.
Network → Interfaces → Create New → Interface → Type: VDOM Link
Name: np. vlink-a – FortiGate tworzy automatycznie parę: vlink-a0 (w jednym VDOM) i vlink-a1 (w drugim)
Przypisz vlink-a0 do VDOMu KLIENT-A, vlink-a1 do VDOMu root
Nadaj im adresy IP (np. 169.254.10.1/30 i 169.254.10.2/30 – link-local)
W root: utwórz politykę KLIENT-A → WAN z NAT, w KLIENT-A: utwórz default route przez vlink-a0
Inter-VDOM Link przez CLI
# Utwórz parę vdom-link (w kontekście global)
config global
config system vdom-link
  edit "vlink-a"
    set vcluster-id 0
  next
end

# Przypisz interfejsy do VDOMów i nadaj IP
config system interface
  edit "vlink-a0"
    set vdom "KLIENT-A"
    set ip 169.254.10.1 255.255.255.252
    set allowaccess ping
  next
  edit "vlink-a1"
    set vdom "root"
    set ip 169.254.10.2 255.255.255.252
  next
end

# Default route w KLIENT-A przez vlink
config vdom
  edit "KLIENT-A"
config router static
  edit 1
    set gateway 169.254.10.2
    set device "vlink-a0"
  next
end

GUI
▾
