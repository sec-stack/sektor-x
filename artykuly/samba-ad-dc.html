Teoria i porównanie
Samba AD DC — co to jest i kiedy używać
TEORIA
▾
Samba 4 to open-source implementacja protokołów Microsoft Active Directory. Pozwala Linuxowi działać jako pełnoprawny Domain Controller — obsługuje Kerberos, LDAP, DNS, GPO i replikację, tak jak Windows Server.
Kluczowe komponenty
Kerberos (MIT) — uwierzytelnianie użytkowników i komputerów w domenie
LDAP — baza danych użytkowników, grup, komputerów, polityk
DNS — krytyczny element AD — nazwa domeny musi rozwiązywać się przez DNS
SMB/CIFS — udostępnianie plików i drukarek dla Windows
SYSVOL — udział sieciowy z Group Policy Objects (GPO)
FunkcjaWindows Server ADSamba AD DC
Kerberos✓ Pełny✓ Pełny
LDAP✓ Pełny✓ Pełny
GPO✓ Pełny⚡ Przez RSAT
DNS✓ Wbudowany✓ Wbudowany
Replikacja DC✓ Pełna⚡ Podstawowa
Koszt licencji✗ Płatny✓ Darmowy
Dołączanie Win 10/11✓ Tak✓ Tak
ℹ️
Dla 120 użytkowników Windows
Samba AD DC w pełni wystarczy. Obsługuje dołączanie komputerów, logowanie domenowe, GPO przez RSAT, udostępnianie plików. Ograniczenia pojawiają się przy zaawansowanych scenariuszach (fine-grained password policies, complex GPO) — dla typowego biura nie stanowią problemu.
Wymagania sprzętowe i systemowe
WAŻNETEORIA
▾
Samba AD DC jest lekkie — nie wymaga potężnego serwera. Dla 120 użytkowników wystarczy skromna maszyna, fizyczna lub VM.
Minimalne wymagania (120 userów)
CPU: 2 vCPU (lub fizyczne rdzenie)
RAM: 2 GB minimum, 4 GB zalecane
Dysk: 20 GB dla systemu + osobna partycja dla SYSVOL/bazy AD
System: Ubuntu Server 22.04 LTS (zalecany) lub Debian 12
Sieć: Statyczny IP — DC musi mieć stały adres IP
Hostname: Krótki, bez kropek, np. dc01
⚠️
Krytyczne przed instalacją
1. Ustaw statyczny IP — DC z DHCP to przepis na katastrofę
2. Ustaw hostname zanim zaczniesz — zmiana po instalacji niszczy AD
3. Zsynchronizuj czas (NTP) — Kerberos nie toleruje różnicy >5 minut
4. Wyłącz lub skonfiguruj firewall przed instalacją
Planowanie domeny — nazwa, IP, struktura
WAŻNETEORIA
▾
Planowanie domeny to decyzja na lata. Zła nazwa domeny lub złe IP oznaczają bolesną migrację w przyszłości.
Przykładowe planowanie dla firmy
Nazwa domeny AD: firma.local lub ad.firma.pl
Uwaga: Unikaj .local — kolizja z mDNS. Lepiej firma.int lub corp.firma.pl

IP serwera DC: 192.168.1.10 (statyczne, poza pulą DHCP)
Subnet: 192.168.1.0/24
NetBIOS: FIRMA (max 15 znaków, bez kropek)

DNS: DC będzie jedynym DNS dla sieci — komputery Windows jako DNS primary ustawiają IP kontrolera domeny
✅
Rekomendacja dla 120 userów
Użyj subdomeny swojej publicznej domeny: jeśli masz firma.pl, ustaw AD jako ad.firma.pl lub corp.firma.pl. Unikasz konfliktów DNS i masz profesjonalną strukturę. DC hostname: dc01, FQDN: dc01.ad.firma.pl

Przygotowanie systemu
Konfiguracja sieci i hostname przed instalacją
CLIKRYTYCZNE
▾
Zanim dotkniesz Samby — skonfiguruj sieć i hostname. To nieodwracalne po provisioning domeny.
Konfiguracja statycznego IP (Netplan — Ubuntu 22.04)
# Sprawdź nazwę interfejsu sieciowego ip link show # Edytuj konfigurację Netplan sudo nano /etc/netplan/00-installer-config.yaml
# Zawartość pliku — dostosuj do swojej sieci network: version: 2 ethernets: ens18: # zmień na nazwę swojego interfejsu dhcp4: false addresses: - 192.168.1.10/24 routes: - to: default via: 192.168.1.1 nameservers: addresses: [127.0.0.1] # DC sam będzie DNS search: [ad.firma.pl]
# Zastosuj konfigurację sudo netplan apply # Ustaw hostname sudo hostnamectl set-hostname dc01 # Edytuj /etc/hosts sudo nano /etc/hosts
# Zawartość /etc/hosts 127.0.0.1 localhost 192.168.1.10 dc01.ad.firma.pl dc01 # Weryfikacja hostname hostname -f ping -c 2 dc01.ad.firma.pl
Instalacja pakietów Samba
CLIKRYTYCZNE
▾
Instalujemy Sambę z repozytoriów Ubuntu. Samba 4.x jest wystarczająca — nie musisz kompilować ze źródeł.
# Aktualizacja systemu sudo apt update && sudo apt upgrade -y # Instalacja Samba i narzędzi sudo apt install -y \ samba \ samba-dsdb-modules \ samba-vfs-modules \ winbind \ libpam-winbind \ libnss-winbind \ krb5-user \ dnsutils \ net-tools # Podczas instalacji krb5-user zostaniesz zapytany o realm # Wpisz domenę WIELKIMI LITERAMI: AD.FIRMA.PL
# Zatrzymaj i wyłącz domyślne usługi Samba przed provisioningiem sudo systemctl stop smbd nmbd winbind sudo systemctl disable smbd nmbd winbind # Usuń domyślny smb.conf sudo mv /etc/samba/smb.conf /etc/samba/smb.conf.bak
Provisioning domeny — samba-tool domain provision
CLIKRYTYCZNE
▾
Provisioning to jednorazowa inicjalizacja domeny — tworzy bazę LDAP, Kerberos, DNS, SYSVOL. Wykonaj raz i ostrożnie.
sudo samba-tool domain provision \ --use-rfc2307 \ --realm=AD.FIRMA.PL \ --domain=FIRMA \ --server-role=dc \ --dns-backend=SAMBA_INTERNAL \ --adminpass='TwojeHaslo123!'
Parametry provisioning
--use-rfc2307 — dodaje atrybuty POSIX (UID/GID) do obiektów AD — ważne dla integracji Linux
--realm — pełna nazwa domeny WIELKIMI LITERAMI (Kerberos realm)
--domain — NetBIOS name (max 15 znaków, wielkie litery)
--server-role=dc — rola Domain Controller
--dns-backend=SAMBA_INTERNAL — Samba zarządza DNS (najłatwiejsza opcja)
--adminpass — hasło konta Administrator domeny (min. złożoność Windows)
# Po provisioning — skopiuj krb5.conf sudo cp /var/lib/samba/private/krb5.conf /etc/krb5.conf # Włącz i uruchom samba-ad-dc sudo systemctl unmask samba-ad-dc sudo systemctl enable samba-ad-dc sudo systemctl start samba-ad-dc # Sprawdź status sudo systemctl status samba-ad-dc
✅
Weryfikacja po provisioning
samba-tool domain level show — pokaże poziom domeny (Windows 2008 R2+)
samba-tool user list — pokaże konto Administrator
host -t SRV _kerberos._udp.ad.firma.pl 127.0.0.1 — DNS działa

Konfiguracja DNS
DNS to serce Active Directory. Bez poprawnego DNS nic nie działa. Konfiguracja, testowanie i troubleshooting DNS w Samba AD.
⏱ 1–2 godziny • priorytet: KRYTYCZNY
Konfiguracja i weryfikacja DNS
Dlaczego DNS jest krytyczny dla AD
TEORIAWAŻNE
▾
Active Directory używa DNS do wszystkiego — znajdowania kontrolerów domeny, usług Kerberos, replikacji. Komputer Windows szuka DC przez rekordy SRV w DNS.
Kluczowe rekordy DNS w AD
_kerberos._udp.DOMENA — lokalizacja serwera Kerberos (port 88)
_ldap._tcp.DOMENA — lokalizacja LDAP (port 389)
_kpasswd._udp.DOMENA — zmiana hasła Kerberos (port 464)
dc01.ad.firma.pl A 192.168.1.10 — adres DC

Komputer który chce dołączyć do domeny robi: DNS lookup → znajdź DC → połącz się z Kerberos → uwierzytelnij
Testowanie DNS po instalacji
CLIWAŻNE
▾
Przed podłączeniem pierwszego komputera Windows — zweryfikuj że wszystkie rekordy DNS są poprawne.
# Testuj DNS z serwera DC (odpytuj lokalnie) host -t SRV _kerberos._udp.ad.firma.pl 127.0.0.1 host -t SRV _ldap._tcp.ad.firma.pl 127.0.0.1 host -t A dc01.ad.firma.pl 127.0.0.1 # Sprawdź Kerberos — pobierz ticket dla Administratora kinit Administrator@AD.FIRMA.PL klist # Pełny test samba-tool sudo samba-tool domain level show sudo samba-tool dns serverinfo 127.0.0.1
🚨
Najczęstszy problem — resolv.conf
Serwer DC musi odpytywać siebie jako DNS. Sprawdź cat /etc/resolv.conf — musi zawierać nameserver 127.0.0.1. Jeśli nie — Ubuntu może nadpisywać resolv.conf przez systemd-resolved. Wyłącz to: sudo systemctl disable systemd-resolved i ustaw ręcznie.
# Fix dla systemd-resolved (Ubuntu 22.04) sudo systemctl disable systemd-resolved sudo systemctl stop systemd-resolved sudo rm /etc/resolv.conf echo "nameserver 127.0.0.1" | sudo tee /etc/resolv.conf sudo chattr +i /etc/resolv.conf # zablokuj przed nadpisaniem

Zarządzanie obiektami AD
Tworzenie użytkowników przez samba-tool
CLI
▾
Samba-tool user to podstawowe narzędzie do zarządzania kontami. Możesz też używać RSAT z Windows.
# Utwórz użytkownika sudo samba-tool user create jan.kowalski 'Haslo123!' \ --given-name="Jan" \ --surname="Kowalski" \ --mail-address="jan.kowalski@firma.pl" \ --department="IT" # Lista użytkowników sudo samba-tool user list # Szczegóły użytkownika sudo samba-tool user show jan.kowalski # Reset hasła sudo samba-tool user setpassword jan.kowalski --newpassword='NoweHaslo123!' # Wyłącz/włącz konto sudo samba-tool user disable jan.kowalski sudo samba-tool user enable jan.kowalski
Jednostki organizacyjne (OU) — struktura dla 120 userów
CLIWAŻNE
▾
OU to foldery w AD — organizują użytkowników i komputery oraz pozwalają stosować GPO do konkretnych grup.
# Utwórz OU dla użytkowników sudo samba-tool ou create "OU=Uzytkownicy,DC=ad,DC=firma,DC=pl" sudo samba-tool ou create "OU=IT,OU=Uzytkownicy,DC=ad,DC=firma,DC=pl" sudo samba-tool ou create "OU=Biuro,OU=Uzytkownicy,DC=ad,DC=firma,DC=pl" sudo samba-tool ou create "OU=Komputery,DC=ad,DC=firma,DC=pl" sudo samba-tool ou create "OU=Drukarki,DC=ad,DC=firma,DC=pl" # Przenieś użytkownika do OU sudo samba-tool user move jan.kowalski "OU=IT,OU=Uzytkownicy,DC=ad,DC=firma,DC=pl"
Import 120 użytkowników z CSV
CLIAUTOMATYZACJA
▾
Tworzenie 120 userów ręcznie? Nie. Skrypt bash + plik CSV robi to w minutę.
# Format pliku users.csv: # username,firstname,lastname,email,department,ou # jan.kowalski,Jan,Kowalski,j.kowalski@firma.pl,IT,IT # anna.nowak,Anna,Nowak,a.nowak@firma.pl,Biuro,Biuro
#!/bin/bash # import-users.sh — import użytkowników z CSV DOMAIN="DC=ad,DC=firma,DC=pl" DEFAULT_PASS="Tymczasowe123!" while IFS=, read -r username firstname lastname email dept ou; do # Pomiń nagłówek [[ "$username" == "username" ]] && continue echo "Tworzę: $username" samba-tool user create "$username" "$DEFAULT_PASS" \ --given-name="$firstname" \ --surname="$lastname" \ --mail-address="$email" \ --department="$dept" # Przenieś do właściwego OU samba-tool user move "$username" \ "OU=$ou,OU=Uzytkownicy,$DOMAIN" # Wymuś zmianę hasła przy pierwszym logowaniu samba-tool user setexpiry "$username" --days=0 done < users.csv echo "Import zakończony!"
# Uruchom skrypt sudo bash import-users.sh

⏱ 1–2 godziny • priorytet: WYSOKI
Dołączanie Windows do domeny
Przygotowanie komputera Windows przed dołączeniem
GUIWAŻNE
▾
Przed dołączeniem do domeny komputer Windows musi mieć poprawnie skonfigurowany DNS — wskazujący na serwer Samba DC.
DNS Primary: Ustaw IP serwera DC (np. 192.168.1.10) jako główny DNS. Ustawienia → Sieć → Właściwości adaptera → IPv4
Ping DC: Przetestuj ping dc01.ad.firma.pl — musi odpowiadać. Jeśli nie — problem z DNS
Czas: Upewnij się że godzina na stacji jest zgodna z DC (±5 min). Kerberos wymaga synchronizacji czasu
Nazwa komputera: Ustaw sensowną nazwę zanim dołączysz do domeny (np. PC-KOWALSKI)
Dołączenie do domeny — GUI i PowerShell
GUIPowerShell
▾
Dołączenie przez GUI lub PowerShell — wynik ten sam. PowerShell przydatny przy masowym deploymencie.
GUI: Ustawienia → System → Informacje → Zmień nazwę komputera → Domena → wpisz ad.firma.pl
Wpisz dane konta z uprawnieniami do dołączania komputerów (Administrator lub dedykowane konto)
Restart — po restarcie pojawi się opcja logowania domenowego
PowerShell — dołączenie do domeny
# PowerShell jako Administrator Add-Computer -DomainName "ad.firma.pl" ` -Credential "FIRMA\Administrator" ` -OUPath "OU=Komputery,DC=ad,DC=firma,DC=pl" ` -Restart
# Weryfikacja po restarcie — sprawdź domenę (Get-WmiObject Win32_ComputerSystem).Domain systeminfo | findstr /i "domain" # Test Kerberos z PowerShell klist
⚠️
Typowe błędy przy dołączaniu
"Domena nie znaleziona" — zły DNS na stacji, sprawdź czy DC IP jest jako Primary DNS
"Czas różni się" — synchronizuj czas: w32tm /resync /force
"Odmowa dostępu" — złe hasło lub brak uprawnień konta do Join Domain

RSAT i Group Policy
Instalacja RSAT na Windows 10/11
GUIPowerShell
▾
RSAT (Remote Server Administration Tools) to zestaw narzędzi Microsoft do zarządzania AD z poziomu Windows 10/11. Przez RSAT zarządzasz Samba AD jak Windows Server AD.
# PowerShell — instalacja RSAT (Windows 10/11) Get-WindowsCapability -Name RSAT* -Online | ` Add-WindowsCapability -Online # Lub tylko narzędzia AD i GPO Add-WindowsCapability -Online -Name Rsat.ActiveDirectory.DS-LDS.Tools~~~~0.0.1.0 Add-WindowsCapability -Online -Name Rsat.GroupPolicy.Management.Tools~~~~0.0.1.0
Po instalacji: Start → Windows Administrative Tools → Active Directory Users and Computers
Zaloguj się jako FIRMA\Administrator
Zobaczysz strukturę domeny identyczną jak w Windows Server AD
Podstawowe GPO — polityka haseł i mapowanie dysków
GUIWAŻNE
▾
GPO stosujemy do OU — polityki dziedziczą się w dół struktury. Zacznij od dwóch najważniejszych: polityki haseł i mapowania dysków sieciowych.
Group Policy Management → kliknij prawym na domenę → Create a GPO → nazwa np. Polityka-Hasel
Edytuj GPO → Computer Configuration → Windows Settings → Security Settings → Account Policies → Password Policy
Ustaw: min. długość 10 znaków, złożoność włączona, historia 10 haseł, max wiek 90 dni
Mapowanie dysku: User Configuration → Preferences → Windows Settings → Drive Maps → New Mapped Drive
Wpisz ścieżkę UNC: \\dc01\share, literę dysku np. Z:, zaznacz Reconnect
✅
Użyteczne GPO dla biura 120 userów
Polityka haseł, mapowanie dysków działowych, blokada CMD i Rejestru dla zwykłych userów, automatyczna aktualizacja Windows, wyłączenie USB storage, konfiguracja proxy, wallpaper firmowy

Konfiguracja udziałów działowych w smb.conf
CLIWAŻNE
▾
Udziały SMB to foldery sieciowe dostępne dla użytkowników Windows. Uprawnienia zarządzasz przez grupy AD.
# Utwórz foldery na udziały sudo mkdir -p /srv/samba/{IT,Biuro,Wspolny} sudo chmod 0770 /srv/samba/{IT,Biuro,Wspolny} sudo chown root:"FIRMA\IT" /srv/samba/IT sudo chown root:"FIRMA\Biuro" /srv/samba/Biuro sudo chown root:"FIRMA\Domain Users" /srv/samba/Wspolny
# Dodaj udziały do smb.conf sudo nano /etc/samba/smb.conf
# Sekcje do dodania w smb.conf [IT] path = /srv/samba/IT valid users = @"FIRMA\IT" read only = no browseable = yes [Biuro] path = /srv/samba/Biuro valid users = @"FIRMA\Biuro" read only = no browseable = yes [Wspolny] path = /srv/samba/Wspolny valid users = @"FIRMA\Domain Users" read only = no browseable = yes
# Sprawdź poprawność smb.conf i restart sudo testparm sudo systemctl restart samba-ad-dc

Monitoring i backup
Backup bazy Active Directory
CLIKRYTYCZNE
▾
Baza AD to serce całej infrastruktury — jej utrata oznacza utratę wszystkich kont, grup i polityk. Backup codziennie.
#!/bin/bash # backup-ad.sh — backup Samba AD DC DATE=$(date +%Y-%m-%d) BACKUP_DIR="/backup/samba" mkdir -p $BACKUP_DIR # Backup bazy Samba (online — nie wymaga stopu usługi) samba-tool domain backup online \ --targetdir=$BACKUP_DIR \ --server=dc01 \ -U Administrator # Backup smb.conf i krb5.conf cp /etc/samba/smb.conf $BACKUP_DIR/smb.conf.$DATE cp /etc/krb5.conf $BACKUP_DIR/krb5.conf.$DATE # Usuń backupy starsze niż 30 dni find $BACKUP_DIR -mtime +30 -delete echo "Backup AD zakończony: $DATE"
# Dodaj do crona — backup o 2:00 w nocy sudo crontab -e # Dodaj linię: 0 2 * * * /usr/local/bin/backup-ad.sh >> /var/log/backup-ad.log 2>&1
