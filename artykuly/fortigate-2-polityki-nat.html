Faza druga
Firewall i Polityki
Serce FortiGate. Polityki decydują co może przejść przez firewall, w którą stronę i z jakimi profilami bezpieczeństwa. To najważniejsza umiejętność admina.
⏱ 2–3 tygodnie • priorytet: KRYTYCZNY
Logika i teoria
✓
Jak działają polityki – przepływ pakietu przez FortiGate
TEORIAKLUCZOWE
▾
Pakiet wchodzący do FortiGate przechodzi przez ściśle określony pipeline. Zrozumienie kolejności przetwarzania to fundament diagnostyki.
Kolejność przetwarzania pakietu
1. Routing – FortiGate sprawdza tablicę routingu: skąd i dokąd pakiet jedzie
2. Session Lookup – czy to nowa czy istniejąca sesja? (stateful firewall)
3. DoS Policy – ochrona przed atakami DoS (opcjonalne)
4. Firewall Policy – pierwsza pasująca reguła od góry listy wygrywa → ACCEPT lub DENY
5. Security Profiles – AV, IPS, Web Filter, App Control (tylko dla ACCEPT)
6. NAT – tłumaczenie adresów (Source NAT dla wyjścia do internetu)
7. Forwarding – pakiet zostaje wysłany dalej
ℹ️
Stateful vs Stateless
FortiGate to firewall stateful – śledzi sesje TCP/UDP. Jeśli akceptujesz ruch LAN→WAN, odpowiedź z WAN→LAN jest automatycznie przepuszczana bez dodatkowej reguły. Nie musisz tworzyć reguły "powrotnej".
✓
Obiekty adresów i grupy – buduj przed politykami
GUIWAŻNE
▾
Zamiast wpisywać surowe IP w politykach, twórz obiekty adresów. Gdy zmieni się IP drukarki, zmienisz go raz w obiekcie – polityki zaktualizują się automatycznie.
Policy & Objects → Addresses → Create New → Address
Typy obiektów: Subnet (zakres sieci), IP Range (np. 10.10.0.20-10.10.0.30), FQDN (nazwa DNS), Wildcard FQDN (*.google.com)
Utwórz: DRUKARKI = 10.10.0.20-10.10.0.29, TELEFONY_VOIP = 10.10.0.30-10.10.0.50, SERWERY = 10.10.0.10-10.10.0.15
Grupy: Policy & Objects → Addresses → Create New → Address Group. Pogrupuj DRUKARKI + TELEFONY jako URZADZENIA_BIUROWE
Tworzenie obiektu adresu przez CLI
config firewall address
  edit "DRUKARKI"
    set type iprange
    set start-ip 10.10.0.20
    set end-ip 10.10.0.29
    set comment "Drukarki biurowe – piętro 1 i 2"
  next
end
✓
Pierwsza polityka: LAN → Internet (z NAT)
GUISTART
▾
To podstawowa reguła, bez której userzy nie mają internetu. Ruch z LAN wychodzi na WAN z translacją adresu (NAT) – zewnętrzny świat widzi publiczny IP FortiGate, nie prywatne IP usera.
Policy & Objects → Firewall Policy → Create New
Name: LAN-do-Internet
Incoming Interface: internal (LAN)
Outgoing Interface: wan1
Source: all (lub obiekt LAN_USERS)
Destination: all
Service: ALL (na start, zawęź później)
Action: ACCEPT
NAT: ON → "Use Outgoing Interface Address" (FortiGate podstawia swój IP WAN)
Logging: Log Allowed Traffic → All Sessions (obowiązkowo!)
Kliknij OK – testuj przez ping z komputera usera
⚠️
Zasada minimalnych uprawnień
Reguła ALL→ALL jest dobra na start, ale docelowo zawęź Service do potrzebnych protokołów: HTTP, HTTPS, DNS, SMTP, IMAP, POP3. Blokowanie niepotrzebnych portów zmniejsza ryzyko ataków i C2 (command & control botnetów).
✓
Polityki dla drukarek – ograniczenie ruchu
GUIBEZP.
▾
Drukarki sieciowe nie powinny mieć dostępu do internetu – to potencjalny wektor ataku. Skonfiguruj politykę pozwalającą tylko na drukowanie i zarządzanie w sieci LAN.
PortProtokółZastosowanie
9100TCPRAW printing (JetDirect) – podstawowe drukowanie
631TCPIPP – Internet Printing Protocol
161UDPSNMP – monitorowanie stanu drukarki
80/443TCPPanel web drukarki (zarządzanie)
515TCPLPR/LPD – starszy protokół druku
Utwórz Custom Service: Policy & Objects → Services → Create New → nazwa: DRUKOWANIE, dodaj porty TCP 9100, 631, 515 i UDP 161
Utwórz politykę: Src = DRUKARKI, Dst = all (LAN), Service = DRUKOWANIE, Action = ACCEPT
Utwórz politykę blokującą wyjście drukarek na internet: Src = DRUKARKI, Dst = all, Out = wan1, Action = DENY
Kolejność: reguła DENY dla drukarek PRZED ogólną regułą LAN→Internet!
✓
Virtual IPs i NAT – dostęp z zewnątrz do wewnętrznych zasobów
GUICLI
▾
Virtual IP (VIP) to mechanizm Destination NAT – mapujesz zewnętrzny IP i port na wewnętrzny serwer. Używaj np. do udostępnienia serwera plików lub kamery IP z zewnątrz.
Policy & Objects → Virtual IPs → Create New → Virtual IP
External IP: publiczny IP FortiGate (lub zakres)
Mapped IP: wewnętrzny IP serwera, np. 10.10.0.11
Włącz Port Forwarding jeśli chcesz mapować tylko jeden port (np. zewnętrzny 8443 → wewnętrzny 443)
Utwórz politykę: In = wan1, Out = internal, Dst = VIP, Service = HTTPS, Action = ACCEPT
🚨
Bezpieczeństwo VIP
Każdy VIP to "dziura" do sieci wewnętrznej. Zawsze: ograniczaj Source w polityce do konkretnych IP (np. tylko siedziba centrali), włącz IPS na tej polityce, używaj niestandardowych portów zewnętrznych.
✓
Policy Lookup i diagnostyka polityk
GUICLITIP
▾
Zanim zadzwoni user z "internet nie działa" – wiesz gdzie szukać. Trzy kluczowe narzędzia diagnostyczne polityk.
1. Policy Lookup (GUI)
Policy & Objects → Policy Lookup. Wpisz: Source IP, Destination IP, Protocol/Port. Wynik: która reguła pasuje i co robi. Idealne do testowania przed wdrożeniem.
2. Logi ruchu (GUI)
Log & Report → Forward Traffic. Filtruj po IP źródłowym usera. Kolumna "Policy" pokazuje numer reguły, "Action" = accept/deny. Kliknij na log → szczegóły sesji.
3. Debug flow (CLI) – najpotężniejsze narzędzie
# Krok 1: Wyczyść poprzednie flagi
diagnose debug reset

# Krok 2: Ustaw filtr na IP usera
diagnose debug flow filter addr 10.10.0.55

# Krok 3: Włącz trace (6 = szczegółowy)
diagnose debug flow trace start 100
diagnose debug enable

# Obserwuj output – user generuje ruch
# Po zakończeniu:
diagnose debug disable
diagnose debug reset
✅
Odczyt debug flow
Szukaj linii: iprope_in_check() check failed on policy X – oznacza blokadę przez regułę X. Linia find a route: gw-X.X.X.X via wan1 – pakiet ma trasę. no session matched – nowa sesja, sprawdzana przez polityki.
